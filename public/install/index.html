Install the full PostSteward runtime

Keep planning and schedules on your machine, with social account credentials held by PostSteward Cloud. Choose local or hosted execution for the workspace.

curl -fsSL --proto '=https' --tlsv1.2 https://poststeward.com/install.sh | bash

Requires Python 3.10 or newer and Bash. Linux is the current verified installation platform. Owner workspace access remains restricted; public signup is a separate launch milestone.

To install and inspect before pairing, append bash -s -- --no-onboard in place of bash. Review the installer and stable release metadata.

Pair, configure, then activate

  1. Run the installer and open its pairing link. Sign in and approve the exact machine details.
  2. Connect or select your verified X and Threads accounts in the owner workspace. LinkedIn Page access requires its separately approved application and provider permissions.
  3. Run poststeward configure --help to configure your local projects and reviewed campaign content, then poststeward doctor to inspect readiness.
  4. Review the switch to your paired local executor in the owner workspace. Preview and apply poststeward activate using its exact review digest.
  5. Inspect scheduled work and provider receipts. A reservation or successful command acknowledgement is distinct from verified publication.

An installation starts with automation inactive. The owner reviews executor handoff and activation before unattended local publishing.

Let a remote agent work with the local runtime

Give the agent an owner-issued token with explicit read/schedule scopes. Remote MCP exposes runtime_inspect, runtime_schedule_create, runtime_schedule_cancel and runtime_command_get when the workspace executes locally.

The active run-due service polls commands outbound. For one manual poll use poststeward cloud bridge. Inspect the command receipt after a lost response; reuse the original key and avoid blind retries.

For migration or dead-machine recovery, pair the target as a new installation. After local verification run poststeward cloud recovery-review, then approve its digest and new target in the owner workspace.
