User data deletion

You can remove PostSteward's locally held workspace data and connected credentials. Deleting PostSteward data does not automatically delete posts or revoke every grant held by an external social platform.

Effective date: 19 September 2026 · Contact: community@oneclickpostfactory.com

Option 1 — Delete from the connected workspace

  1. [01]

    Sign in as the workspace owner

    Use the same verified owner identity that controls the PostSteward workspace.

  2. [02]

    Open the Lifecycle / deletion controls

    Workspace deletion is an owner-only operation and requires a current owner session and explicit confirmation.

  3. [03]

    Confirm the exact deletion phrase

    The workspace shows the exact confirmation phrase. This prevents an agent or accidental click from erasing the workspace.

  4. [04]

    Allow any in-flight provider effect to settle

    If a provider write may already be in flight, PostSteward keeps the workspace fenced until the bounded effect window is safe to clear. It does not erase evidence while a write may still be executing.

What completed workspace deletion removes

  • —Owner sessions and scoped agent grants for that workspace.
  • —Locally stored provider access/refresh credentials and pending provider OAuth state.
  • —Projects, campaigns, schedules, automation state and workspace application records.
  • —Private-source links and locally stored encrypted credentials for connected private sources.
  • —Workspace billing mappings, recovery coordinator rows and external-effect rows after the safety settlement gate completes.

A minimal completed-deletion tombstone may remain so an old backup or restored state cannot recreate the deleted workspace's publishing authority.

Option 2 — Request deletion by email

If you cannot access the workspace, email community@oneclickpostfactory.com with the subject PostSteward data deletion request.

Include the email address used to sign in and enough information to identify the workspace. We may need to verify that you control the owner identity before processing the request. Do not send passwords, API keys, access tokens, recovery keys or social-provider secrets.

Threads / Meta and other provider data

PostSteward removes locally usable provider credentials during workspace deletion, but provider-side authorisation grants and already-published social posts live on the external provider. If you want the provider's own copy or grant removed, also use that provider's account/app controls.

For Threads/Meta, you can remove the PostSteward app's access from the relevant Meta account settings in addition to deleting the PostSteward workspace. Removing provider access does not itself erase a post that has already been published; delete that content through the social platform if required.

Questions or confirmation

For deletion status or privacy questions, contact community@oneclickpostfactory.com.
